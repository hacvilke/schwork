# Contributing to Schwork

We build **one subject at a time** so every published subject is thorough, accurate, and easy to study on a phone.

## Code Readability & Contributor Standards

Every file in this repository should be easy for a human contributor (including students learning web dev) to read, review in a pull request, and tweak safely:

1. **One responsibility per file**
   - Every UI component keeps its own dedicated CSS Module right beside it (e.g. `QuickCheck.tsx` + `QuickCheck.module.css`) so changing one card never breaks another.
   - Pure math or formatting logic lives in small helper files (such as `src/utils/mathParser.ts` and `src/components/lesson/graphMath.ts`) separated from React rendering code.
2. **Plain, descriptive names**
   - Avoid cryptic abbreviations (`sx`, `tx`, `pt`, `v`). Prefer self-explanatory names (`svgX`, `tickStep`, `selectedOption`, `isExpanded`).
3. **Clear prop docs & "why" comments**
   - Every exported component has a 1–2 line top-of-file summary and JSDoc comments on its props interface so contributors know how to tweak it without reading the entire implementation.
   - Add short comments explaining *why* a non-obvious rule exists (such as asymptote breaks or `localStorage` privacy guards), not obvious syntax.
4. **Consistent formatting**
   - Follow `.editorconfig` (2 spaces for TS/JS/CSS/MD, 4 spaces for Python, LF line endings).
5. **Test & verify before opening a PR**
   ```bash
   npm test
   npm run typecheck
   npm run build
   npm run build:gh-pages
   ```

## Trademark & Naming Rule

Do **not** use "CXC" or "CSEC" in site headings, page titles, lesson copy, or diagrams. Keep student-facing copy focused on Jamaican secondary school study (Grades 10–11, Paper 1 / Paper 2, SBA, Learning Objectives). Trademark disclosures belong only in `CREDITS.md` and `docs/credits.md`.

## Adding a New Subject (One at a Time)

1. **Create the subject directory** under `docs/<subject-slug>/`:
   ```text
   docs/mathematics/
   ├── index.md
   ├── section-1-number-theory/
   │   ├── _category_.json
   │   └── 01-number-sets.mdx
   ```
2. **Add a dedicated sidebar** in `sidebars.ts`:
   ```ts
   mathematicsSidebar: [{type: 'autogenerated', dirName: 'mathematics'}],
   ```
3. **Register the subject** in `src/data/subjects.ts` (`status: 'live'`, `docPath: '/docs/mathematics'`) and add a link in `docusaurus.config.ts`.
4. **Run all checks** (`npm test && npm run typecheck && npm run build && npm run build:gh-pages`).

## Built-in MDX Lesson Components

All components in `src/components/lesson/` are globally registered via `src/theme/MDXComponents.tsx` (no imports needed in `.mdx` files):

- `<SyllabusHeader subject="..." section="..." code="..." papers={['Paper 1', 'Paper 2']} studyTime="15 min" difficulty="Core" />`
- `<ObjectivesBox id="unique-lesson-id" objectives={['...', '...']} />`
- `<FormulaCard title="..." onFormulaSheet={true | false}>...</FormulaCard>`
- `<InteractiveGraph title="..." curves={[...]} parameters={[...]} />`
- `<DiagramFigure src="/img/diagrams/..." alt="..." caption="..." />`
- `<WorkedExample title="..." marks={4} problem={...} examTip="...">...</WorkedExample>`
- `<QuickCheck paper="Paper 1" marks={1} question="..." options={[...]} correctIndex={0} explanation="..." />`

## Math & Diagrams Standard

- **Default:** Use **KaTeX** (`$...$` / `$$...$$`) for equations and **`<InteractiveGraph />`** for interactive function/coordinate plots.
- **Selective static SVGs:** Use Python **Matplotlib** (`scripts/matplotlib/`) only when an interactive graph cannot draw the figure (e.g., triangle congruence proofs, vector addition diagrams, optics ray diagrams, or Integrated Science lab diagrams).
  ```bash
  python3 -m venv .venv
  .venv/bin/pip install -r scripts/matplotlib/requirements.txt
  .venv/bin/python scripts/matplotlib/build_all.py
  ```
  Commit the generated SVGs under `static/img/diagrams/` so Vercel and GitHub Pages builds do not require Python.

## Dual Deployment (Vercel + GitHub Pages)

- **Vercel:** Uses `vercel.json` (`npm run build`, `baseUrl: '/'`).
- **GitHub Pages:** Uses `.github/workflows/deploy-gh-pages.yml` (`npm run build:gh-pages`, `baseUrl: '/schwork/'`).
