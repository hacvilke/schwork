## 1. Database Forms & Sub-Forms (Syllabus Objective 6.4a!)

Typing raw data straight into a giant Datasheet table is clunky and error-prone (users can accidentally overwrite the wrong row!). A **Form** provides a **clean, user-friendly on-screen data-entry window** showing **one record at a time** (with crisp boxes, buttons, and drop-downs) for **adding, editing, viewing, and searching records**!

### Key Form Skills (Form Wizard Only!)
- **Using the Form Wizard:** Pick your table/query, select ONLY the suitable fields needed by the clerk, pick a clean layout (`Columnar` for single records, `Tabular` for lists), and give it a clear form title!
- **Main Form + Sub-Form:** Displays data from **TWO linked `1 : M` tables simultaneously on ONE screen**!
  - *Classic SBA Example:* The **Main Form** shows ONE Customer (`CustomerID`, `Name`, `Parish` from `CUSTOMER`), while the embedded **Sub-Form** directly underneath automatically lists **ALL Orders** placed by that exact customer from the linked `ORDER` table!

## 2. Select Queries & The QBE Design Grid (**#1 Paper 2 Database Question!**)

A **Select Query** asks the database a specific question and pulls out **ONLY the exact fields and matching records** you want — without ever modifying the underlying tables!

In Microsoft Access / LibreOffice Base (and directly printed on Paper 2!), queries are built in the **QBE (Query By Example) Design Grid** with **SIX standard rows**:

| QBE Row | What It Controls | Paper 2 Watch-Out! |
| :--- | :--- | :--- |
| **`Field:`** | Exact column name(s) — or a **Calculated Field expression**! | Must spell field names identically to the table! |
| **`Table:`** | Which table that field comes from (`STUDENT`, `ORDER`, etc.). | Essential in **multi-table queries**! |
| **`Sort:`** | `Ascending`, `Descending`, or blank (unsorted). | Leftmost sorted column acts as Primary Sort! |
| **`Show:`** | Tick box `[✓]` = visible in output; **UNTICKED `[ ]`** = hidden from display *(used ONLY for filtering criteria!)*! | **CLASSIC PAPER 2 TRAP!** Count ONLY ticked **`Show: [✓]`** columns when asked *"How many fields will be displayed?"*! |
| **`Criteria:`** | First filter row — entries on the **SAME row combine with `AND`**! | Text wrapped in `"..."`, dates in `#...#` (`#01/01/2026#`)! |
| **`Or:`** | Second filter row — entries on **DIFFERENT rows combine with `OR`**! | Always check whether a condition sits on the `Criteria:` row (`AND`) or drops to the `Or:` row (`OR`)! |

## 3. Relational & Logical Criteria Operators in Queries

| Operator | Exact Meaning | Query Criteria Example | Matches… |
| :---: | :--- | :--- | :--- |
| `=` *(often omitted)* | Equal to | `"Kingston"` or `=50` | Exact match `"Kingston"` or `50` |
| `<>` | **Not equal to** | `<>"Pending"` | Every status EXCEPT `"Pending"` |
| `>`, `<`, `>=`, `<=` | Greater/Less than (or equal) | `>=80` | Scores `80` and above |
| **`AND`** | **BOTH** conditions true *(same cell OR same row)* | `>=50 AND <=79` | Scores from `50` through `79` inclusive |
| **`OR`** | **EITHER** condition true *(same cell OR `Or:` row)* | `"Kingston" OR "St James"` | Records in Kingston OR St James |
| **`BETWEEN ... AND ...`** | Inclusive range (numbers or dates!) | `Between 50 And 79` or `Between #01/01/2026# And #31/03/2026#` | Any number `50–79` or date in Q1 2026 |
| **`LIKE`** *(with wildcard `*`)* | Pattern matching text! | `Like "C*"` *(starts with C)*; `Like "*son"` *(ends with son)* | `"Campbell"`, `"Clarke"`; `"Johnson"`, `"Morrison"` |
| **`NOT`** | Negates a condition | `Not "Cancelled"` | Everything except `"Cancelled"` |

## 4. Calculated Fields in Queries (**Must-Know SBA & Paper 2 Syntax!**)

Never store calculated columns (like `TotalCost` or `NetPay`) permanently inside a raw database table (because if `UnitPrice` changes later, a stored total becomes stale!). Instead, compute them **dynamically inside a Select Query** using a **Calculated Field**:

```text
NewFieldName: [Field1] * [Field2]
```

### Exact Syntax Rules for Calculated Fields
1. Type the **brand-new column name FIRST**, followed IMMEDIATELY by a **colon (`:`)** — **NO equals sign `=`** *(unlike Excel!)*!
2. Wrap existing table field names inside **square brackets `[...]`** (especially mandatory if a field name contains spaces!).
3. **Examples:**
   - `GrossPay: [HoursWorked] * [HourlyRate]`
   - `GCT: [Subtotal] * 0.15`
   - `DiscountedPrice: [UnitPrice] * 0.90`
   - `FullName: [FirstName] & " " & [LastName]` *(joins two text fields with a space!)*

## 5. Worked Example: Reading & Designing a Multi-Table QBE Query (Paper 2!)

<WorkedExample
  title="Examining a Multi-Table Select Query with Hidden Criteria & Calculated Field"
  marks={10}
  problem={
    <>
      A Jamaican music store links tables <strong><code>CUSTOMER</code></strong> (<code>CustID</code>, <code>FirstName</code>, <code>LastName</code>, <code>Parish</code>) and <strong><code>ORDER</code></strong> (<code>OrderID</code>, <code>CustID</code>, <code>Qty</code>, <code>UnitPrice</code>, <code>Paid</code>).
      <br />
      (a) Complete a QBE Design Grid to display <code>FirstName</code>, <code>LastName</code>, <code>Parish</code>, and a calculated field <strong><code>OrderTotal</code></strong> (<code>Qty × UnitPrice</code>) for customers in <strong><code>Kingston</code> OR <code>St Catherine</code></strong> whose orders are <strong>unpaid (<code>Paid = No</code>)</strong>, sorted alphabetically by <code>LastName</code> — WITHOUT displaying the <code>Paid</code> column in the final result!
      <br />
      (b) How many fields will appear in the output when this query runs?
    </>
  }
  examTip="LOOK CAREFULLY at the logic for 'Kingston OR St Catherine AND Paid = No'! If you put 'Kingston' and 'No' on Row 1, and ONLY 'St Catherine' on Row 2 (leaving Paid blank on Row 2!), Access will pull PAID orders from St Catherine too! Whenever you drop to the Or: row, REPEAT any shared AND criteria (No) on BOTH rows — OR put 'Kingston' Or 'St Catherine' inside ONE cell on the Criteria row so Paid = No applies cleanly to both!"
>

### (a) QBE Design Grid *(Cleanest, Bug-Free Solution!)*

| QBE Row | Col 1 | Col 2 | Col 3 | Col 4 | Col 5 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Field:** | `FirstName` | `LastName` | `Parish` | `OrderTotal: [Qty]*[UnitPrice]` | `Paid` |
| **Table:** | `CUSTOMER` | `CUSTOMER` | `CUSTOMER` | *(calculated)* | `ORDER` |
| **Sort:** | | `Ascending` | | | |
| **Show:** | `[✓]` | `[✓]` | `[✓]` | `[✓]` | **`[ ]`** *(unticked!)* |
| **Criteria:** | | | `"Kingston" Or "St Catherine"` | | `No` |
| **Or:** | | | | | |

### (b) Number of Fields Displayed
- **4 fields** (`FirstName`, `LastName`, `Parish`, and `OrderTotal`) — because **`Paid` has its `Show` box UNTICKED** so it filters silently in the background!

</WorkedExample>
