## 1. What Is a Database Report? (Query vs Form vs Report!)

Students sometimes mix up **Forms**, **Queries**, and **Reports** on Paper 1 — remember their exact distinct roles:
- **Table:** Stores raw data.
- **Form:** User-friendly **screen interface for entering and editing** records.
- **Query:** **Filters, calculates, and pulls** specific records dynamically.
- **Report:** Formats data from tables and/or queries into a **polished, presentation-ready, read-only summary document** built for **management review, printing, or PDF distribution**! *(You CANNOT type new records into a Report!)*

---

## 2. Four Essential Report Features (Directly Tested in SBA & Paper 2!)

### 1. Creating Reports via the Report Wizard
1. Select your **base Table(s) or Select Query** *(for SBA: combine fields across **TWO or THREE related tables** — or base the report straight on your multi-table Select Query!)*.
2. Choose **ONLY the relevant fields** needed by the reader (avoid cramming 15 tiny unreadable columns onto one portrait page — switch to **Landscape** if needed!).
3. Pick a clean layout (`Stepped` or `Block`) and inspect in **Print Preview** so zero text or `###` numbers get cut off!

### 2. Grouping & Sorting Inside a Report
- **Grouping:** Splits records into distinct visual sections under a shared category heading!
  - *Example:* Grouping a national sales report by **`Parish`** creates clean titled sections: **Clarendon**, then **Kingston**, then **St James**!
- **Sorting:** Orders individual detail records *inside* each group (e.g. sorting customers alphabetically by **`LastName` Ascending**, or by **`OrderTotal` Descending**!).

### 3. Statistical & Summary Features (**Group Footer vs Report Footer!**)
Inside the Report Wizard's **`Summary Options…`** button (or Design View), you add automatic totals:
- **`SUM`:** Adds all numeric/currency values (`=Sum([OrderTotal])`).
- **`AVG`:** Computes the average (`=Avg([Score])`).
- **`COUNT`:** Counts how many records appear (`=Count([StudentID])`).
- **`MIN` / `MAX`:** Shows lowest and highest values!

**CRITICAL Distinction Between Report Sections:**
| Report Section | Where It Prints | What Goes Inside It |
| :--- | :--- | :--- |
| **Report Header** | **ONCE** at the very top of Page 1 | Specific Report Title, organisation logo, date |
| **Page Header** | Top of **EVERY page** | Column field headings (`Name`, `OrderTotal`, etc.) |
| **Group Header** | Start of **EACH new group** (e.g. each Parish) | Group heading (`Parish: Kingston`) |
| **Detail** | **Once per individual record** | Actual customer/student rows |
| **Group Footer** | Bottom of **EACH group** | **Subtotals / Group Averages / Group Counts** for THAT parish! |
| **Page Footer** | Bottom of **EVERY page** | Page number (`Page 1 of 4`), print date |
| **Report Footer** | **ONCE** at the very end of the entire report | **Grand Total / Overall Average / Total Record Count** across ALL groups! |

### 4. Specific Report Titles & Output Destinations (Official SBA Mark-Scheme Rule!)
- **Renaming the Report Title:** Access defaults to ugly raw names like `qryUnpaidOrders` or `tblSales`! **ALWAYS rename it to a specific, descriptive management title** — e.g. **`Unpaid Customer Orders by Parish — Q1 2026`** *(the SBA mark scheme awards **2 full marks** for a specific informative title vs only **1 mark** for a generic title like "Orders Report"!)*
- **Three Output Destinations:** Reports can be generated to **(1) Screen (Print Preview)** for quick review, **(2) Printer** (hard copy for meetings), or **(3) File (PDF / XPS / RTF)** to email or link on your SBA website!

## 3. Worked Example: Designing a Grouped Multi-Table Report (Paper 2!)

<WorkedExample
  title="Designing an Executive Sales Summary Report by Parish"
  marks={6}
  problem={
    <>
      A Jamaican distributor wants a polished printed report from its <code>CUSTOMER</code> and <code>ORDER</code> tables showing every order grouped by <strong><code>Parish</code></strong>, sorted from highest to lowest <code>OrderTotal</code> within each parish, displaying <strong>each parish’s subtotal sales</strong> AND the <strong>overall company grand total sales</strong>.
      <br />
      (a) State which <strong>report section</strong> should contain: (i) the report title, (ii) each parish’s subtotal sales, and (iii) the overall company grand total.
      <br />
      (b) Write the exact summary function formula to sum <code>OrderTotal</code>, and suggest a <strong>specific report title</strong> (worth full marks!).
    </>
  }
  examTip="Memorise the two footer rules: Group subtotals ALWAYS live in the Group Footer (prints after each group!), whereas Overall Grand Totals ALWAYS live in the Report Footer (prints ONCE at the very end!). Never put a Grand Total inside the Page Footer!"
>

### (a) Exact Report Sections
- **(i) Report Title:** **Report Header** *(appears once at the top of Page 1)*
- **(ii) Each Parish's Subtotal Sales:** **Group Footer** (`Parish Footer` — recalculates at the end of every parish group!)
- **(iii) Overall Company Grand Total:** **Report Footer** *(appears once at the very end of the report!)*

### (b) Summary Formula & Specific Title
- **Summary Formula:** `=Sum([OrderTotal])` *(placed in both `Parish Footer` for parish subtotals and `Report Footer` for the grand total!)*
- **Specific Report Title:** *"Caribbean Distributors Ltd — Customer Order Revenue Summary by Parish (2026)"*

</WorkedExample>
