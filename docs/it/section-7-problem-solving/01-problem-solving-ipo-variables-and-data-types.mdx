## 1. The Five Steps in Problem-Solving (Syllabus Objective 7.1!)

Computers cannot "think" on their own — they execute **exact, step-by-step instructions** written by humans. Jumping straight to typing code without planning causes messy, buggy programs! Every structured computing solution follows **FIVE official steps**:

1. **Define the Problem:** Read the requirements carefully and identify **exactly what Inputs are given, what Processing/calculations must happen, and what Outputs are required** (using an **IPO Chart**!).
2. **Propose and Evaluate Solutions:** Brainstorm two or more possible ways to solve the problem and compare their accuracy, speed, simplicity, and memory use.
3. **Determine (Select) the Most Efficient Solution:** Choose the clearest, fastest, most reliable approach that solves every requirement cleanly.
4. **Develop and Represent the Algorithm:** Write out the complete step-by-step solution logically as **Pseudocode** and/or a **Flowchart** (before writing actual programming code!).
5. **Test and Validate the Solution:** **Dry-run (desk-check)** the algorithm by hand using realistic test data inside a **Trace Table** to verify that it produces the exact right outputs with zero logic errors!

## 2. Divide-and-Conquer (Top-Down Decomposition — Syllabus Obj 7.2!)

**Divide-and-Conquer** means breaking one large, overwhelming problem into **smaller, simpler, independent sub-tasks** until each small piece is easy to solve!
- **Everyday Example — Preparing a 3-Course Jamaican Dinner:** Instead of panicking over one giant task, decompose it into: *(1) Prepare Starter (Soup)* → *(2) Prepare Main Course (Rice & Peas + Stew Chicken)* → *(3) Prepare Dessert (Sweet Potato Pudding)* → *(4) Serve Meal*!
- **Computing Example — School Report Card System:** Break into: *(1) Read student marks* → *(2) Validate marks (`0–100`)* → *(3) Compute average & grade* → *(4) Print formatted report card*!

## 3. Defining Diagrams — IPO Charts (**Guaranteed Paper 2 Marks!**)

An **IPO Chart** (*Input – Processing – Output Defining Diagram*) decomposes any problem into its **three essential building blocks**!

| Column | What You Write Inside It | Key Tip (Don't Lose Marks!) |
| :--- | :--- | :--- |
| **INPUT** | The **exact raw data items** the user/system must supply (nouns/variable names — e.g. `ItemPrice`, `Quantity`, `TaxRate`). | **NEVER include calculated results** here! Only raw data entered from outside! |
| **PROCESSING** | Short **action verbs / steps** transforming inputs into outputs (e.g. *Read inputs*, *Calculate Subtotal = ItemPrice × Quantity*, *Check if Subtotal > 5000*, *Display Total*). | Always use **action verbs** (`Accept/Read`, `Calculate/Compute`, `Compare/Check`, `Display/Print`)! |
| **OUTPUT** | The **exact final results / messages** displayed or printed for the user (e.g. `Subtotal`, `Discount`, `FinalTotal`). | Check the problem statement's exact words (*"Print the name AND the words 'Refund Due'"*)! |

## 4. Variables vs Constants & Rules for Good Identifiers

Inside computer RAM, programs store values in named memory locations called **Variables** and **Constants**:
- **Variable:** A named storage location in memory whose **value CAN CHANGE** during program execution (e.g. `Score`, `RunningTotal`, `Count`, `StudentName`).
- **Constant:** A named storage location in memory whose **value NEVER CHANGES** while the program runs (e.g. `GCT_RATE = 0.15`, `PI = 3.14159`, `PASS_MARK = 50`).

### Naming Good Identifiers (Mnemonic Variable Names!)
1. **Meaningful (Mnemonic):** Use `ItemPrice`, `StudentAge`, `TotalVotes` — NEVER mysterious letters like `x`, `y`, `z`!
2. **NO spaces allowed!** Use camelCase (`netPay`) or underscores (`net_pay`) — NEVER `net pay`!
3. **Must start with a letter** (or underscore in some languages) — NEVER start with a digit like `1stScore`!
4. **Never use Reserved Words** (`IF`, `WHILE`, `BEGIN`, `END`, `INTEGER`, `PRINT`) as variable names!

## 5. All Five Elementary Data Types (Tested Almost Every Year on Paper 1 & 2!)

Every variable/constant has a **Data Type** telling the computer what kind of data it holds and how much RAM to reserve:

| Data Type | Exact What It Stores | Clean Examples | Classic Exam Trap! |
| :--- | :--- | :--- | :--- |
| **1. Integer** | **Whole numbers ONLY** (positive, negative, or zero — **NO decimal point!**) | `0`, `42`, `-15`, `2026`, `NumStudents`, `ReceiptNumber` | NEVER use Integer for money (`J$49.50`) or averages (`78.6`) — decimals get chopped off! |
| **2. Real / Floating-Point** *(Float / Double)* | Numbers containing a **fractional / decimal part**! | `3.14`, `19.99`, `-0.5`, `ItemPrice`, `AverageMark`, `Weight` | **Money/Prices, Averages, Percentages & Measurements** are ALWAYS **Real / Floating-Point**! |
| **3. Character (`Char`)** | **EXACTLY ONE single letter, digit, or symbol** (often in single quotes). | `'A'`, `'M'`, `'F'`, `'7'`, `'%'`, `GradeLetter`, `MiddleInitial` | Only ONE character! `"Pass"` or `"Male"` is NOT a Character — it's a **String**! |
| **4. String** | A **sequence of characters** (words, sentences, names, phone numbers, codes with letters & digits). | `"Kingston"`, `"K. Brown"`, `"876-555-0192"`, `"STU-041"` | **Codes like `"STU-041"` or Phone Numbers** are ALWAYS **String**! |
| **5. Boolean** *(Logical)* | **ONLY ONE of two truth values:** **`TRUE`** or **`FALSE`**! | `InStock = TRUE`, `IsPassed = FALSE`, `RefundDue = TRUE` | Never store `"Yes"` as Boolean — Boolean strictly holds **`TRUE` / `FALSE`**! |

## 6. Worked Example: IPO Chart & Data Type Selection (Paper 2!)

<WorkedExample
  title="Building an IPO Chart & Choosing Variable Data Types (Real Exam Pattern)"
  marks={10}
  problem={
    <>
      A Jamaican delivery company wants an algorithm that accepts a customer’s <strong>Name</strong>, <strong>ParcelWeight</strong> (in kg, e.g. 2.5 kg), <strong>NumberOfItems</strong> (whole number), and whether they chose <strong>ExpressDelivery</strong> (True/False).
      <br />
      • Standard delivery costs <strong>J$400 per kg</strong> (fixed constant <code>RATE_PER_KG = 400</code>).
      <br />
      • If <code>ExpressDelivery</code> is <code>TRUE</code>, add a flat <strong>J$600 express fee</strong>.
      <br />
      • Output the customer’s <strong>Name</strong> and <strong>TotalCost</strong>.
      <br />
      (a) Construct the <strong>Defining Diagram (IPO Chart)</strong> for this problem.
      <br />
      (b) State whether <code>RATE_PER_KG</code> is a <strong>Variable or Constant</strong>, and state the exact <strong>Data Type</strong> for: <code>CustomerName</code>, <code>ParcelWeight</code>, <code>NumberOfItems</code>, <code>ExpressDelivery</code>, and <code>ZoneCode</code> (single letter <code>'A'</code>, <code>'B'</code>, or <code>'C'</code>).
    </>
  }
  examTip="Notice how clean the IPO Chart is: INPUT lists ONLY the raw inputs accepted from the user (never TotalCost!), PROCESSING lists action verbs in exact sequence, and OUTPUT lists ONLY what is displayed!"
>

### (a) Defining Diagram (IPO Chart)

| INPUT | PROCESSING | OUTPUT |
| :--- | :--- | :--- |
| • `CustomerName`<br/>• `ParcelWeight`<br/>• `NumberOfItems`<br/>• `ExpressDelivery` | 1. Prompt for and accept `CustomerName`, `ParcelWeight`, `NumberOfItems`, and `ExpressDelivery`.<br/>2. Calculate `BaseCost = ParcelWeight * RATE_PER_KG`.<br/>3. If `ExpressDelivery = TRUE`, add `600` to `BaseCost` to get `TotalCost`; else `TotalCost = BaseCost`.<br/>4. Display `CustomerName` and `TotalCost`. | • `CustomerName`<br/>• `TotalCost` |

### (b) Constant vs Variable & Data Types
- **`RATE_PER_KG = 400`:** **Constant** *(value stays fixed at 400 throughout program execution)*.
- **Data Types:**
  - `CustomerName` → **String** *(multiple characters/words)*
  - `ParcelWeight` → **Real / Floating-Point** *(allows decimals like `2.5` kg)*
  - `NumberOfItems` → **Integer** *(whole number count)*
  - `ExpressDelivery` → **Boolean** *(only `TRUE` or `FALSE`)*
  - `ZoneCode` (`'A'`, `'B'`, `'C'`) → **Character** *(single letter!)*

</WorkedExample>
