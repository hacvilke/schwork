## 1. The Internet vs The World Wide Web (WWW)

Students often treat these two terms as identical — **examiners NEVER do!**
- **The Internet:** The **global physical network of interconnected computers, cables, routers, and satellites** (the "highways and roads" infrastructure!).
- **The World Wide Web (WWW):** **ONE major information service running ON TOP of the Internet** — a massive collection of interlinked web pages and multimedia documents accessed via web browsers! *(Other services running on the Internet include **Email**, **FTP**, **VoIP/WhatsApp calls**, and **online multiplayer games**!)*

---

## 2. How All Key Web Technologies Fit Together (Syllabus Objective 2.4!)

Imagine you tap a link on your phone to open a Schwork study lesson. In less than half a second, **all these core web technologies work as one team**:

```text
  [1. USER types URL or clicks HYPERLINK inside WEB BROWSER]
                           │
        (2. Sends HTTP / HTTPS request across the Internet)
                           ▼
        [3. WEB SERVER locates requested HTML WEB PAGE file]
                           │
        (4. DOWNLOADS HTML, images & styles back to browser)
                           ▼
        [5. WEB BROWSER renders the formatted page on screen!]
```

### Master Glossary of All 11 Syllabus Web Technology Concepts

| Web Technology Term | Clear, Exam-Ready Definition |
| :--- | :--- |
| **1. World Wide Web (WWW)** | A global system of interlinked hypertext web pages and multimedia resources hosted on web servers across the Internet. |
| **2. Web Page** | A single electronic document on the WWW (containing text, images, videos, and hyperlinks); a collection of related web pages under one domain forms a **Website** (starting at its **Home Page**). |
| **3. HTML** *(HyperText Markup Language)* | The **standard markup language** using tags (like `<h1>`, `<p>`, `<a href="...">`, `<img>`) that defines the **structure and content** of a web page so browsers know how to display it! |
| **4. HTTP / HTTPS** *(HyperText Transfer Protocol [Secure])* | The **set of communication rules (protocol)** governing how web browsers request web pages and how web servers transmit them back! **`HTTPS`** encrypts the traffic (padlock icon!) to protect passwords and credit cards from eavesdropping! |
| **5. Web Browser** | Client application software (e.g. **Google Chrome, Mozilla Firefox, Microsoft Edge, Apple Safari**) that requests, interprets HTML, and displays web pages on your screen! |
| **6. Web Server** | A dedicated, always-on high-capacity computer (plus server software) that **stores website files** and delivers ("serves") web pages to browsers whenever requested! |
| **7. Hyperlink (Link)** | A clickable word, button, or image embedded in a web page that **jumps directly** to another web page, another spot on the same page, an email address, or a downloadable file! |
| **8. URL** *(Uniform Resource Locator)* | The **unique web address** specifying the exact protocol, server domain, and file path of a resource on the Internet! |
| **9. FTP** *(File Transfer Protocol)* | A specialised Internet protocol designed specifically for **transferring large files reliably** between a local computer and a remote server (e.g. a web developer uploading an entire finished website to a hosting server!). |
| **10. Upload vs Download** | • **Upload:** Sending/copying data **FROM your local device UP TO a remote server** (e.g. submitting your SBA PDF to Google Classroom or posting a video to YouTube).<br/>• **Download:** Receiving/copying data **FROM a remote server DOWN TO your local device** (e.g. saving a past paper PDF onto your phone!). |
| **11. Email** *(Electronic Mail)* | Internet service for sending and receiving digital text messages and file attachments almost instantaneously to unique electronic addresses (`student@school.edu.jm`). |

## 3. Anatomy of a URL (Frequently Tested on Paper 1 & 2!)

Look closely at every piece of a real URL:

`https://www.schwork.edu.jm/docs/it/networks.html`

| Part of URL | Example Above | Meaning |
| :--- | :--- | :--- |
| **Protocol (Scheme)** | `https://` | Communication rules used (`https` = encrypted secure web transfer; `http` = unencrypted; `ftp` = file transfer). |
| **Subdomain / Host** | `www` | Identifies the World Wide Web host server (optional on modern sites). |
| **Domain Name** | `schwork.edu.jm` | Human-friendly unique name mapped to the server's IP address (via DNS): `schwork` = organisation, **`.edu`** = educational Top-Level Domain (TLD), **`.jm`** = **Jamaica country code**! |
| **Path & File Name** | `/docs/it/networks.html` | Exact folder path (`/docs/it/`) and specific web page file (`networks.html`) on that server! |

**Common Top-Level Domains (TLDs):** `.com` (commercial), `.org` (non-profit organisation), `.edu` (education), `.gov` (government — e.g. `moey.gov.jm`), `.net` (network/ISP), `.jm` (Jamaica), `.tt` (Trinidad & Tobago), `.bb` (Barbados).

## 4. Electronic Mail (Email) — Key Fields & Smart Usage

When sending a formal school or business email, examiners test whether you know **CC vs BCC**!
- **`To:`** Primary recipient(s) who must read and act on the email.
- **`CC:` (Carbon Copy):** Secondary recipients sent a copy for their information — **EVERY recipient can see everyone else's email address in `To` and `CC`!**
- **`BCC:` (Blind Carbon Copy):** Recipients receive a copy **privately — their email addresses are HIDDEN from all other recipients!** *(Essential for protecting privacy when emailing 200 parents or clients at once!)*
- **`Subject:`** Crisp one-line summary of the email topic.
- **`Attachment:`** Digital file (`.docx`, `.pdf`, `.xlsx`, `.jpg`) sent alongside the message *(watch size limits — typically ~25 MB — and beware suspicious `.exe`/macro attachments carrying malware!)*.

## 5. Worked Example: Explaining Web Loading & Dissecting a URL

<WorkedExample
  title="Tracing a Web Request & Dissecting a URL (Paper 2 Style)"
  marks={8}
  problem={
    <>
      A student opens Chrome on her laptop, types <code>https://www.moey.gov.jm/exams/timetable.pdf</code>, and saves the file to her laptop.
      <br />
      (a) Identify the <strong>(i) Protocol</strong>, <strong>(ii) Domain Name</strong>, <strong>(iii) Country Code</strong>, and <strong>(iv) File Name</strong> from the URL above.
      <br />
      (b) Is saving <code>timetable.pdf</code> onto her laptop an <strong>Upload</strong> or a <strong>Download</strong>?
      <br />
      (c) Explain clearly how the <strong>Web Browser</strong>, <strong>HTTPS</strong>, and the <strong>Web Server</strong> interact to deliver that file.
    </>
  }
  examTip="Always explain BOTH sides of HTTPS when asked about security: it uses HTTP rules to request/transfer web resources AND encrypts the communication so attackers on public Wi-Fi cannot read or tamper with it!"
>

### (a) URL Breakdown
- **(i) Protocol:** `https` *(HyperText Transfer Protocol Secure)*
- **(ii) Domain Name:** `moey.gov.jm` *(or `www.moey.gov.jm`)*
- **(iii) Country Code:** `.jm` *(Jamaica)*
- **(iv) File Name:** `timetable.pdf`

### (b) Upload or Download?
- **Download** — the file is copied **from a remote web server down onto her local laptop**.

### (c) How Browser, HTTPS & Web Server Interact
1. The **Web Browser** (Chrome) reads the typed **URL** and sends a secure encrypted request using the **HTTPS** protocol across the Internet to the Ministry's **Web Server**.
2. The **Web Server** locates `/exams/timetable.pdf` on its storage and transmits it securely back via **HTTPS**.
3. The **Web Browser** receives and saves/displays the PDF on the student's laptop!

</WorkedExample>
